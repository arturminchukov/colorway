# Боковая панель, режимы favicon и пипетка без плавающего окна

Дата: 2026-07-30

## Задача

Расширение работает, но работать с ним неудобно. Правила живут только на странице настроек, popup
показывает лишь статус, а пипетка рисует поверх страницы плавающую панель, которая прыгает при
каждом выборе. Нужен один экран, где видно текущий сайт со всеми его правилами и где выбранный
элемент появляется сразу — вместе с полями цвета.

Плюс favicon перестаёт быть только «буквы на цвете»: появляются три режима, включая перекраску
родной иконки сайта, чтобы сайт оставался узнаваемым, а инстанс — различимым.

## Отношение к прежним решениям

Работа над универсальной пипеткой завершена; эта спека её переделывает в трёх местах и **отменяет
одно прежнее правило**.

**Отменяется:** требование «текст UI — на русском» из спек `2026-07-28` и `2026-07-29`. Весь
интерфейс расширения и README переходят на **английский**. Комментарии в коде остаются английскими,
как и раньше. Это решение владельца; следующий исполнитель должен читать эту спеку, а не прежние.

**Удаляется:** popup целиком (`src/popup/`), плавающая панель пипетки (`src/content/picker/panel.ts`)
и всё, что существовало только ради неё — расчёт положения над/под элементом, предпросмотр из
пипетки, доступ пипетки к хранилищу, очередь записей между сессиями, защита от двойного сохранения.

**Остаётся без изменений:** подбор профиля по паттернам, префикс заголовка вкладки, инжектор стилей,
подбор селектора, защита селектора от инъекции, динамическая регистрация content script под выданные
права, страница настроек как место для профилей и URL-паттернов.

**Миграции нет.** Проект на стадии MVP, пользователей нет. `version` поднимается до `3`, профили
старой формы не проходят валидацию и отбрасываются при загрузке; настройка заводится заново.

## Поверхности

| поверхность | ответственность |
|---|---|
| боковая панель (новая) | текущий сайт: домен, тумблер профиля, favicon с подписью, правила, добавление правила |
| страница настроек | список профилей, их URL-паттерны, удаление профиля — и больше ничего |
| пипетка | подсветка и один клик; сообщает панели селектор и выключается |

Редактор правил со страницы настроек **убирается**: правила и настройки favicon правятся только в
боковой панели, на сайте, к которому они относятся. Иначе одну и ту же запись правят два места, и мы
возвращаем гонку, которую эта переделка как раз убирает. Страница настроек показывает у каждого
профиля только счётчик правил; чтобы их изменить, нужно открыть сам сайт.

Клик по иконке расширения открывает боковую панель: в Chrome через `side_panel` и
`sidePanel.setPanelBehavior({ openPanelOnActionClick: true })`, в Firefox через `sidebar_action` и
`sidebarAction.open()` из обработчика клика по действию. Различие изолируется в адаптере
`src/shared/` — манифесты и так генерируются раздельно.

**Права не расширяются.** `tabs` не добавляется: панель узнаёт вкладку через `activeTab` и через
host-права уже настроенных сайтов. Следствие, которое нужно показать пользователю, а не прятать: для
сайта, где доступ уже выдан, панель видит вкладку свободно и обновляется при переключении; для нового
сайта — только после клика по иконке. Пока адрес неизвестен, панель говорит «нажми иконку, чтобы
работать с этой вкладкой», а не показывает пустоту.

## Модель данных

```ts
type FaviconMode = "original" | "tinted" | "initials";

type ColorRule = {
  id: string;
  selector: string;
  background: string | null;   // null = не трогать это свойство
  text: string | null;
};

type Profile = {
  id: string;
  name: string;
  enabled: boolean;
  patterns: string[];
  /** Подпись рядом с иконкой во вкладке. */
  titlePrefix: string;
  faviconMode: FaviconMode;
  /** Цвет перекраски в режиме tinted, фон букв в режиме initials. */
  faviconColor: string;
  /** Используется только в режиме initials. */
  faviconLetters: string;
  rules: ColorRule[];
};

type Settings = { version: 3; profiles: Profile[] };
```

`faviconBackground` из прежней модели переименован в `faviconColor`: он теперь описывает цвет в двух
разных режимах, и слово «background» стало неточным.

Цвета по-прежнему только `#rgb`/`#rrggbb`: они попадают в инжектируемый CSS и в генерируемый SVG.

## Три режима favicon

| режим | что происходит |
|---|---|
| `original` | расширение не подменяет иконку вовсе; инстанс различается подписью вкладки и цветами на странице |
| `tinted` | иконка сайта сохраняет форму и заливается выбранным цветом целиком — силуэт; сайт узнаётся по очертаниям |
| `initials` | иконка заменяется цветным квадратом с одной-двумя буквами; прежнее поведение расширения |

В переключателе режимов показывается не только название, но и получающаяся иконка — выбор понятен
без чтения. Поле букв отображается только в режиме `initials`: в двух других оно ни на что не влияет.

### Перекраска в режиме tinted

Делает content script, а не панель: он живёт в origin страницы, поэтому иконка сайта для него своя.

Порядок: взять самый крупный `<link rel~="icon">`, объявленный страницей, иначе `/favicon.ico` →
загрузить в `Image` → нарисовать в `<canvas>` → `globalCompositeOperation = "source-in"` и залить
выбранным цветом → получить силуэт исходной формы → `toDataURL()`.

Три способа провалиться ведут в одно место: иконка с чужого домена без CORS (`toDataURL` бросает
`SecurityError`), иконка не загрузилась, иконки нет вовсе. Во всех случаях — откат на сгенерированную
иконку с буквами того же цвета, и панель отдельной строкой объясняет, почему получились буквы вместо
силуэта. Молча подменять режим нельзя: пользователь выбрал `tinted` и должен понимать, что видит.

Результат перекраски кешируется в памяти по паре «адрес иконки + цвет». Без кеша аппликатор, который
переприменяется на каждой мутации SPA, перерисовывал бы canvas десятки раз в секунду.

## Боковая панель

Порядок сверху вниз:

1. **Предпросмотр вкладки** — настоящая иконка сайта (`tab.favIconUrl`) и заголовок, отрисованные так,
   как их увидишь: с учётом выбранного режима favicon и префикса. Виден всегда, а не только при
   правке favicon: панель выбрана ради него.
2. **Домен и тумблер** профиля. Тумблер выключает профиль целиком — правила, favicon и подпись; сайт
   возвращается к исходному виду без перезагрузки.
3. **`Change favicon`** — свёрнутая строка с итогом: образец цвета, название режима, префикс.
   Раскрывается вниз и содержит переключатель трёх режимов с превью, образец цвета под подписью
   `Favicon`, поле букв (только в `initials`) и поле `Tab prefix`. Подпись вкладки живёт здесь же:
   это то, что стоит рядом с иконкой, и по решению владельца это одна настройка на сайт.
4. **`Rules`** — список: образцы цветов, селектор моно-шрифтом, точка состояния, кнопка удаления.
   Клик по строке раскрывает правку цветов. Только что выбранное правило появляется раскрытым с
   меткой `NEW`.
5. **`+ Add rule`** — запрашивает host-право на текущий домен и включает пипетку.
6. **Подвал** — сколько правил ничего не находит, и ссылка на страницу настроек.

Точка состояния правила: красит · ничего не находит сейчас · не покрасит никогда (нет цвета,
недопустимый или неразбираемый селектор).

**Правки применяются сразу, без кнопки сохранения.** Панель постоянная, страница рядом: пользователь
крутит цвет и видит результат. Запись в хранилище отложенная. Кнопка «Сохранить» здесь была бы лишним
шагом между действием и результатом.

**Панель — единственный, кто пишет правила и настройки favicon.** Пипетка теряет доступ к хранилищу
вовсе: она сообщает селектор, а правило создаёт панель. Страница настроек пишет только паттерны и
удаление профиля целиком — по этим полям она с панелью не пересекается. Так исчезает класс гонок, с
которым боролась прошлая итерация: двух конкурентных `load`+`save` по одному и тому же полю больше
не существует физически.

Отложенная запись — 300 мс после последнего изменения. Раскрыто одновременно одно правило: клик по
другой строке сворачивает предыдущую, иначе список из десятка правил перестаёт быть обозримым.

Правило без выбранного цвета — нормальное состояние, а не ошибка: сразу после выбора элемента цвета
ещё нет. Такое правило сохраняется и показывается точкой «не покрасит никогда», пока цвет не задан.

`permissions.request()` вызывается из панели первым `await` после клика — панель является страницей
расширения, а клик по `+ Add rule` пользовательским жестом. Иначе Firefox отклонит запрос.

## Пипетка

Остаётся: подсветка под курсором с меткой «тег · размер», подбор селектора, выход по `Esc`, перехват
клика в фазе capture с `preventDefault` и `stopPropagation` — чтобы клик выбора не сработал как
обычный клик по сайту.

Добавляется: по клику пипетка отправляет панели `{ selector }` и **сама выключается**. Одно нажатие
`+ Add rule` — один выбранный элемент. Если панель к этому моменту закрыли, у сообщения нет
получателя: пипетка гаснет, ничего не записав.

Вид подсветки обновляется: тонкая рамка акцентного цвета и скруглённая метка с тенью вместо прежнего
прямоугольного ярлыка.

### Предпросмотр цвета

Раньше его рисовала пипетка. Теперь цвет выбирают в панели, а запись отложенная — ждать её означало
бы видимый лаг. Поэтому панель, пока пользователь меняет цвет, посылает content script'у сообщение
«покажи вот это», тот применяет отдельным временным `<style>` мгновенно. Когда отложенная запись
срабатывает, правило становится настоящим и временный стиль снимается.

## Архитектура

```
src/
  core/                     чистая логика, тестируется без DOM и браузерных API
    profile.ts              + FaviconMode, faviconColor, version 3
    favicon.ts              buildInitialsDataUrl (как есть) + faviconPlan(profile)
    ruleEdits.ts            НОВЫЙ: чистые правки настроек — добавить, изменить, удалить правило
    theme.ts, selector.ts, matcher.ts, permissions.ts, title.ts    без изменений
  content/
    index.ts                + канал предпросмотра, + режимы favicon
    faviconTint.ts          НОВЫЙ: перекраска через canvas, кеш, откат
    faviconApplier.ts, titleApplier.ts, styleInjector.ts           без изменений
    picker/
      index.ts              подсветка и один клик; сообщает селектор
      highlight.ts          обновлённый вид рамки и метки
      selectorBuilder.ts    без изменений
      panel.ts              УДАЛЯЕТСЯ
  sidepanel/                НОВЫЙ каталог: разметка и логика панели
  options/                  профили и URL-паттерны
  background/index.ts       + открытие панели по клику, + запуск пипетки
  shared/browser.ts         + адаптер боковой панели Chrome/Firefox
  popup/                    УДАЛЯЕТСЯ
```

`faviconPlan(profile)` — чистая функция, отвечающая на вопрос «что за иконку строить». Content script
исполняет её решение, но не принимает его:

```ts
type FaviconPlan =
  | { kind: "keep" }                                  // ничего не подменять
  | { kind: "tint"; color: string }                   // перекрасить родную иконку
  | { kind: "initials"; letters: string; color: string };

function faviconPlan(profile: Profile): FaviconPlan;
```

Невалидный цвет или пустые буквы дают `{ kind: "keep" }`: лучше не тронуть иконку вовсе, чем
подменить её на заведомо сломанную.

`ruleEdits.ts` выносит из панели всю содержательную работу с настройками, чтобы рискованная часть
была чистой и покрытой тестами, а в панели осталась только разметка и обработчики.

## Тестирование

Чистые тесты (vitest, рядом с исходником):

- `favicon.test.ts` — `faviconPlan` для каждого режима, включая режим `original` (ничего не строить)
  и `initials` с пустыми буквами;
- `ruleEdits.test.ts` — добавление правила, правка цвета, удаление, отсутствие мутации входа;
- `profile.test.ts`, `theme.test.ts`, `selector.test.ts`, `matcher.test.ts`, `permissions.test.ts`,
  `title.test.ts`, `settingsRepo.test.ts` — обновляются под новую форму профиля.

Тесты на jsdom:

- `faviconTint.test.ts` — подставной `Image`: успешная перекраска, откат при `SecurityError`, откат
  при неудачной загрузке, попадание в кеш при повторном запросе;
- `picker/highlight.test.ts`, `picker/selectorBuilder.test.ts` — остаются;
- `idempotency.test.ts` — остаётся: инвариант «повторное применение не порождает мутацию в области
  наблюдения аппликатора» по-прежнему обязателен, его нарушение однажды вешало вкладку.

Разметка боковой панели и страницы настроек тестами не покрывается — они проверяются вручную по
чек-листу в README. Именно поэтому вся их содержательная логика вынесена в `ruleEdits.ts`.

## Риски

| риск | реакция |
|---|---|
| `sidePanel` и `sidebar_action` — разные API | один адаптер в `src/shared/`; минимальные версии браузеров в README |
| Без права `tabs` панель не видит новый сайт до клика по иконке | панель честно объясняет это состояние, а не показывает пустоту |
| Отложенная запись плюс правка из настроек | панель — единственный писатель данных сайта; страница настроек перечитывает хранилище перед записью |
| Иконка с чужого домена не перекрашивается | откат на буквы того же цвета и объяснение в панели |
| Перерисовка canvas на каждой мутации SPA | кеш по паре «адрес иконки + цвет» |
| Английский UI противоречит двум прежним спекам | отмена зафиксирована в разделе «Отношение к прежним решениям» |

## Границы

Не входит в объём: горячая клавиша для пипетки; правка CSS-свойств кроме цвета фона и текста;
выбор нескольких элементов за один запуск пипетки; загрузка своего файла иконки; экспорт и импорт
настроек; `storage.sync`; перетаскивание порядка правил; готовые пресеты для популярных сайтов;
публикация в сторах.

# Универсальная пипетка: перекраска любого сайта по выбранным элементам

Дата: 2026-07-29

## Задача

Расширение умеет перекрашивать только vmui: селекторы `.vm-header*` вшиты в код, а поля профиля
(`accent`, `headerBackground`, `logoColor`, `logoCaption`) описывают именно его шапку. Нужно снять
это ограничение: пользователь наводит мышь на любой элемент любой страницы — как в devtools, —
выбирает цвет фона и текста, и правило сохраняется для домена этой страницы.

Исходная цель расширения не меняется: инстансы (prod, staging, dev) должны опознаваться с одного
взгляда. Меняется способ — вместо готового знания про vmui пользователь показывает пальцем.

## Отношение к текущему коду

Работа над vmui-версией сохранена в ветке `vmui-specific` (коммит `b6d642d`). Основная ветка
переходит на универсальную модель без обратной совместимости.

**Уходит:** поля `accent`, `headerBackground`, `logoColor`, `logoCaption`; модуль
`src/content/logoBadge.ts` целиком; вшитые селекторы `.vm-header*` внутри `buildCss`.

**Остаётся без изменений:** подбор профиля по паттернам (`matcher.ts`), префикс заголовка вкладки
(`title.ts`, `titleApplier.ts`), генерация favicon (`favicon.ts`, `faviconApplier.ts`), инжектор
стилей (`styleInjector.ts`), работа с наборами паттернов (`permissions.ts`), репозиторий настроек,
динамическая регистрация content script под выданные права.

**Миграции нет.** Проект на стадии разработки: профили старой формы не проходят валидацию
`isProfile` и отбрасываются при загрузке, настройки начинаются пустыми. `version` поднимается
до `2`, чтобы отличать форму данных в будущем.

## Модель данных

```ts
type ColorRule = {
  id: string;
  /** CSS-селектор: подобран пипеткой или отредактирован вручную. */
  selector: string;
  /** null означает «не трогать это свойство». */
  background: string | null;
  text: string | null;
};

type Profile = {
  id: string;
  name: string;
  enabled: boolean;
  /** Match patterns; подставляется из хоста страницы как "*://<host>/*". */
  patterns: string[];
  titlePrefix: string;
  faviconLetters: string;
  /** Фон генерируемой иконки: собственное поле, фона шапки больше нет. */
  faviconBackground: string;
  rules: ColorRule[];
};

type Settings = { version: 2; profiles: Profile[] };
```

Разделение ответственности: профиль описывает вкладку (какие URL, префикс заголовка, иконка),
правило — один элемент на странице. Один профиль содержит много правил.

Цвета по-прежнему только `#rgb`/`#rrggbb`: они попадают в инжектируемый CSS.

## Архитектура

```
src/
  core/                      чистая логика, тестируется без DOM и без браузерных API
    profile.ts               типы Profile / ColorRule / Settings, дефолты, createProfile
    matcher.ts               без изменений
    permissions.ts           без изменений
    title.ts                 без изменений
    favicon.ts               без изменений
    theme.ts                 isValidColor, contrastText; buildCss переписан под список правил
    selector.ts              НОВЫЙ: фильтр стабильности токенов и защита от инъекции
  content/
    index.ts                 bootstrap; по сообщению из popup динамически грузит пипетку
    styleInjector.ts         без изменений
    faviconApplier.ts        без изменений
    titleApplier.ts          без изменений
    picker/                  НОВЫЙ каталог, грузится только в режиме пипетки
      index.ts               режим целиком: старт, остановка по Esc, передача выбора панели
      highlight.ts           рамка под курсором и подпись «тег + размер»
      selectorBuilder.ts     обход дерева: элемент → селектор-кандидат
      panel.ts               панель у элемента в Shadow DOM
  background/index.ts        регистрация скриптов; запуск пипетки по запросу popup
  storage/settingsRepo.ts    валидация под новую форму (включая массив правил)
  options/                   список профилей; правила редактируются в карточке профиля
  popup/                     статус вкладки, тумблер, кнопка «Выбрать элемент»
  shared/browser.ts          без изменений
```

`buildCss(profile)` обходит `rules` и для каждого валидного правила порождает
`selector { background: … !important; color: … !important }`, пропуская незаданные свойства.
`!important` обязателен по прежней причине: сайты задают цвета инлайном.

Пипетка подключается через динамический `import()` из `content/index.ts` и не попадает в основную
сборку content script: обычная перекраска остаётся такой же лёгкой, как сейчас.

## Пипетка

**Подсветка.** При движении мыши элемент под курсором получает рамку и подпись с тегом и размером,
как в devtools. Клик фиксирует выбор, `Esc` выходит из режима.

**Панель** рендерится в Shadow DOM: стили сайта до неё не достают, её собственные не текут наружу
(`all: initial` внутри корня, максимальный `z-index`). Содержит редактируемое поле селектора,
живой счётчик совпадений `querySelectorAll(...).length`, два выбора цвета (фон и текст),
кнопки сохранения и отмены.

Панель встаёт над или под выбранным элементом — там, где есть место, — и никогда не закрывает сам
элемент. Это компенсирует главный недостаток выбранного варианта размещения.

И подсветка, и панель помечены собственным атрибутом и исключены из подбора: кликнуть по
собственному интерфейсу расширения нельзя.

**Предпросмотр.** Пока правило редактируется, цвета применяются через отдельный временный
`<style>`. Отмена снимает его целиком — восстанавливать ничего не требуется.

**Область ответственности.** Пипетка только создаёт новые правила. Правка и удаление существующих
живут на странице настроек: в карточке профиля список правил, у каждого — поле селектора, два
выбора цвета и кнопка удаления. Так пипетка остаётся одноразовым сценарием «показал — сохранил»,
а не вторым редактором настроек.

## Подбор селектора

`selectorBuilder.ts` идёт сверху вниз до первого попадания:

1. стабильный `id` → `#id`;
2. семантические атрибуты — `data-testid`, `data-test`, `data-qa`, `aria-label`, `role`, `name`;
3. классы, прошедшие фильтр стабильности;
4. если совпадений всё ещё много — приписать предка слева (`.card > .title`), до трёх уровней;
5. крайний случай — путь с `:nth-of-type`.

Фильтр стабильности (`core/selector.ts`, чистый) отбрасывает то, что меняется от сборки к сборке:
хеши CSS-in-JS (`css-1a2b3c`, `sc-fVvNTt`, `jsx-1234567`), случайные буквенно-цифровые токены и
BEM-модификаторы (`vm-header_app`, `btn--active`) — модификатор описывает состояние, а не
сущность, и селектор с ним отваливается при первой же смене состояния.

Отдельные токены экранируются `CSS.escape`.

## Безопасность

Раньше в инжектируемый CSS попадали только hex-цвета из `<input type="color">`. Теперь туда идёт
произвольный текст из поля селектора, поэтому строка вида `a {} body { display: none }` вставила бы
в страницу чужие правила. Две линии защиты:

- `isSafeSelector()` в ядре — чистая функция, отбрасывающая `{`, `}`, `;`, `@`, `<` и маркеры
  комментариев;
- `CSS.supports('selector(…)')` на странице — настоящий разбор парсером браузера.

`buildCss` пропускает правило, если селектор не прошёл синтаксическую проверку или цвет невалиден.

## Права и поток запуска

Ограничение платформы: `permissions.request()` нельзя вызвать из content script или service worker
— только со страницы расширения по пользовательскому жесту. Клик в popup и есть этот жест.

1. Popup на любом сайте показывает кнопку «Выбрать элемент».
2. Клик → `permissions.request({ origins: ["*://<host>/*"] })` первым `await` после жеста.
3. Права выданы → background внедряет и запускает пипетку, popup закрывается.
4. Пользователь выбирает элемент, цвета, сохраняет.
5. Сохранение пишет в `storage.local` через `settingsRepo` — content script это умеет.
6. `storage.onChanged` → background пересобирает регистрацию; в текущей вкладке правило
   применяется сразу, на будущих загрузках — через зарегистрированный content script.

Отказ в правах: пипетка не запускается, popup объясняет причину. Промежуточного состояния нет.

Если под текущий хост профиля ещё нет, сохранение создаёт его: имя — хост, паттерн — `*://<host>/*`.

Сообщение статуса, которым popup опрашивает страницу, меняет форму: вместо признака «шапка
найдена» content script возвращает число совпадений по каждому правилу
(`{ profileName: string | null; matches: Array<{ ruleId: string; count: number }> }`).

## Тестирование

Чистые тесты (vitest, рядом с исходником):

- `selector.test.ts` — фильтр стабильности (хеши отбрасываются, семантические классы остаются,
  BEM-модификаторы снимаются), `isSafeSelector` на попытках инъекции, экранирование токенов;
- `theme.test.ts` — сборка CSS из списка правил: несколько правил, пропуск незаданных свойств,
  пропуск правила с невалидным цветом, пропуск правила с небезопасным селектором, наличие
  `!important`;
- `settingsRepo.test.ts` — валидация новой формы, включая массив правил и отбрасывание профилей
  старой формы;
- `matcher.test.ts`, `favicon.test.ts`, `title.test.ts`, `permissions.test.ts` — без изменений.

Тесты на jsdom (окружение уже подключено):

- `selectorBuilder` на настоящем дереве: предпочтение `id`, откат к классам, уточнение предком,
  игнорирование собственных узлов пипетки;
- существующий набор `idempotency.test.ts` остаётся; из него уходит блок про подпись у логотипа.

Панель, подсветка и страницы расширения проверяются вручную по чек-листу в README.

## Риски

| Риск | Реакция |
|---|---|
| Селектор перестал находить элемент после обновления сайта | счётчик совпадений в панели; content script возвращает popup число совпадений по каждому правилу, и popup показывает, какие правила ничего не находят |
| Сайт с агрессивными `z-index` перекрывает панель | максимальный `z-index` и `all: initial` внутри Shadow DOM |
| Пипетка на страницах, где content script запрещён (`chrome://`, PDF, страницы стора) | popup определяет это заранее и объясняет |
| Селектор попадает в `html`/`body` целиком | не запрещаем; счётчик и предпросмотр показывают последствия до сохранения |
| Сайт перерисовывает элемент и теряет наши стили | стили инжектируются как CSS, а не пишутся в элемент, поэтому переживают перерисовку |

## Границы

Не входит в объём: горячая клавиша для запуска пипетки; правка произвольных CSS-свойств кроме фона
и цвета текста (рамки, шрифты, размеры); экспорт и импорт настроек; `storage.sync`; перетаскивание
порядка правил и профилей; готовые пресеты для популярных сайтов; публикация в сторах.

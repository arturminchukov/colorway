# Общие секции панели и страницы настроек

Дата: 2026-07-31

## Задача

1. Переименовать раскрывающийся блок `Change favicon` в `Favicon`.
2. Сделать список правил такой же раскрывашкой с заголовком `Content rules` (тот же
   стиль строки, что у favicon).
3. Добавить видимую реакцию на наведение всем кликабельным элементам.
4. Цвета правила показывать группой: иконка + подпись + свотч + иконка возврата к
   оригиналу — отдельно для `fill` и для `text`.
5. Страница настроек показывает то же самое, плюс поле URL-паттернов.

## Границы модулей

Секции перестают быть панельными — их рендерит и options:

```
src/sections/faviconSection.ts     (из src/panel/)
src/sections/rulesSection.ts       (из src/panel/)
src/shared/disclosure.ts           новый: строка-раскрывашка
src/shared/icons.ts                новый: inline-SVG (fill, text, reset)
```

`core/ruleEdits.ts` получает две чистые функции уровня профиля — `patchRule`,
`withoutRule`; существующие `updateRule`/`removeRule` делегируют им. Панель правит
`Settings`, карточка options правит черновик `Profile`; общий код — один.

CSS расслаивается, потому что общие секции живут на двух поверхностях:

```
public/tokens.css     палитра, --space-*, --radius, dark-scheme, [hidden], :focus-visible
public/sections.css   .disclosure, .modes, .rule, .editor, .colors, .color, .dot,
                      .waiting, .section, hover/active — самодостаточно, не зависит
                      от общих правил поверхности (например, от `label`)
public/panel.css      только панельное: шрифт body, .preview, .footer, .profile-off
public/ui.css         только options: ширина страницы, h1, .card, textarea, стек-label
```

Порядок подключения: `tokens.css` → `sections.css` → файл поверхности (чтобы
поверхность могла перекрыть общее; options так убирает боковые отступы у `.disclosure`
и `.section` внутри карточки).

## Секции

### Favicon

Заголовок `Favicon`. Строка строится общим `disclosure()`, поведение прежнее:
состояние «открыт/закрыт» принадлежит вызывающему, не DOM.

### Content rules

Оборачивается в такую же раскрывашку. В свёрнутом виде сводка: до четырёх чипов
цветов правил + счётчик. По умолчанию открыта (это то, что правят чаще всего),
favicon по умолчанию закрыт; секции независимы.

Внутри правила блок цветов:

```
┌ Colors ──────────────────────┐
│ ▧  fill   [■ #2f81f7]   ↺    │
│ A  text   [■ #ffffff]   ↺    │
└──────────────────────────────┘
```

`↺` показывается всегда; при `null` — `disabled` и приглушена (сбрасывать нечего).
Свотч при `null` остаётся пунктирным. Строка цвета — `div.color` с `aria-label` на
`input[type=color]`, а не `<label>`: вложенная в label кнопка — лишний риск, а
подпись всё равно рисуется отдельным элементом.

`renderRulesSection` получает две необязательные возможности:

- `states` — живой статус правил из вкладки; без него точки статуса не рисуются;
- `picker` — `{ pickingRuleId, onPick }`; без него нет кнопки «Select element» и
  состояния ожидания.

Options не передаёт ни того, ни другого: там нет вкладки, у которой можно спросить.

## Наведение

`sections.css` даёт каждому кликабельному элементу видимую реакцию и
`transition: background-color .12s, color .12s`, глушится `prefers-reduced-motion`:

| Элемент | hover | active |
|---|---|---|
| `.rule` | фон `--raised`, скругление | — |
| селектор правила (`.link`) | цвет → `--fg`, подчёркивание | — |
| `×` удаления | фон `--raised`, цвет → `--danger` | сжатие |
| `.disclosure` | фон `--raised` | — |
| `.modes button` (невыбранный) | цвет → `--fg`, фон `--bg` | — |
| `.pick`, `.primary`, `.link` | яркость/фон | `translateY(1px)` |
| `input[type=color]`, `↺` | border/цвет → `--accent` | — |

## Страница настроек

Карточка профиля: `Profile name` → `Enabled` → `▸ Favicon` → `▾ Content rules` →
`URL patterns` → `[Save] [Delete]`.

Карточка держит локальный черновик `Profile`. Коллбэки секций правят черновик:
`onPatch` (живое перетаскивание цвета) только пишет в черновик, `onPatchSettled`
пишет и перерисовывает **только поддерево секций** — textarea с паттернами, поле
имени и строка статуса не трогаются, фокус не теряется.

Save остаётся явным: `permissions.request` обязан быть первым `await` после клика
(требование Firefox), а он нужен только паттернам.

Ключ к тому, чтобы явный Save не затирал чужие правки: карточка помнит **множество
полей, которых она действительно касалась**. При сохранении `next` строится из
свежепрочитанного `previous` и только тронутых полей черновика (плюс `name`,
`enabled`, `patterns`, которые карточка читает из DOM как и раньше). Правило,
добавленное из панели, пока карточка была «грязной», переживает Save карточки,
которая правил не трогала — существующий регресс-тест на это остаётся в силе.

# Палитра цветов: пресеты и сохранённые цвета

Дата: 2026-08-03

## Задача

Выбор цвета сегодня — голый `<input type="color">` в трёх местах: `fill` и `text`
правила и цвет фавиконки. Каждый цвет подбирается заново, и один и тот же
«prod-красный» на десяти сайтах приходится вспоминать по памяти.

1. Набор готовых цветов, доступный сразу.
2. Свои цвета можно сохранить и потом выбрать в один клик.
3. У сохранённого цвета есть имя — необязательное.
4. Точный подбор нативным пикером никуда не девается.

## Решения

- **Попап у свотча.** Клик по свотчу открывает палитру; строки правил остаются
  компактными, а в попапе есть место под имена и управление. Полоса свотчей под
  каждым полем была бы проще в коде, но добавляла бы две строки к каждому правилу и
  не оставляла места для имён.
- **Одна общая палитра на всё расширение**, не по профилю: смысл в том, чтобы один
  цвет означал одну среду на всех сайтах.
- **Сохранение только вручную**, без авто-«недавних»: ничего не появляется в палитре
  само.
- **Всё управление — в попапе.** Отдельной секции Palette на странице настроек нет:
  там те же цветовые поля с тем же попапом.

## Данные

### `src/core/palette.ts` (новый, чистый)

```ts
export type SavedColor = { id: string; value: string; name: string };

/** Presets ship with the code, not with the settings. */
export const PRESET_COLORS: readonly { value: string; name: string }[];

export function normalizeHex(value: string): string | null;
export function saveColor(palette: SavedColor[], value: string, name: string): SavedColor[];
export function renameColor(palette: SavedColor[], id: string, name: string): SavedColor[];
export function removeColor(palette: SavedColor[], id: string): SavedColor[];
```

- `normalizeHex` приводит `#abc`, `ABC123`, `#AABBCC` к `#aabbcc`; всё остальное —
  `null`. Единственное место, где живёт этот разбор: `colorInput()` сегодня проверяет
  формат сам, и после этой работы проверка уезжает сюда.
- `saveColor` дедуплицирует по значению: цвет, который уже есть в палитре, не
  удваивается — у существующей записи обновляется имя (пустое имя существующее не
  затирает). Новые цвета добавляются в конец.
- Пустое имя — законное состояние: свотч тогда подписан своим hex.
- Функции чистые, вход не мутируется — как `ruleEdits.ts`.

Пресеты — 16 цветов, две строки по восемь: red `#ef4444`, orange `#f97316`,
amber `#f59e0b`, yellow `#eab308`, green `#22c55e`, emerald `#10b981`,
teal `#14b8a6`, cyan `#06b6d4`, blue `#3b82f6`, indigo `#6366f1`,
violet `#8b5cf6`, pink `#ec4899`, stone `#78716c`, slate `#64748b`,
white `#ffffff`, ink `#111827`. Светлые и тёмные нужны, потому что то же поле красит
и фон, и текст.

### Настройки

```ts
export type Settings = { version: 4; profiles: Profile[]; palette: SavedColor[] };
```

`settingsRepo.load()` принимает обе версии: `3` читается как есть и дополняется
`palette: []`, `4` — со своей палитрой. Элементы палитры валидируются поштучно и
отбрасываются по одному, как профили сегодня; `value` обязан проходить
`normalizeHex`. Жёсткого лимита на размер палитры нет — сетка Saved скроллится.

Это первая настоящая миграция в проекте: расширение уже опубликовано, и отбросить
профили пользователя при бампе версии, как делали раньше, теперь нельзя.

## Контрол

### `src/shared/colorField.ts` (новый)

Заменяет `colorInput()` во всех трёх точках использования.

```ts
export function colorField(options: {
  /** null means "leave this property alone": dashed, unset swatch. */
  value: string | null;
  ariaLabel: string;
  palette: SavedColor[];
  /** Live edit: write without forcing a re-render (a drag, a click in the palette). */
  onPreview(next: string): void;
  /** Settled: write and re-render (the popover closed). */
  onPick(next: string): void;
  /** The palette itself changed: saved, renamed, removed. Never forces a re-render. */
  onPaletteChange(next: SavedColor[]): void;
}): HTMLElement;
```

Внутри: кнопка-свотч, скрытый нативный `<input type="color">` (его открывает пункт
`Custom…`) и попап. `value === null` рисуется пунктиром, как сейчас; кнопка ↺ рядом
остаётся за секцией, как и была.

`colorInput()` из `shared/controls.ts` не удаляется: он и строит этот скрытый инпут —
но проверку формата отдаёт `normalizeHex`, чтобы разбор hex жил в одном месте.

### Попап

```
┌──────────────────────┐
│ PRESET               │
│ ■ ■ ■ ■ ■ ■ ■ ■      │
│ ■ ■ ■ ■ ■ ■ ■ ■      │
│ SAVED                │
│ ■ ■ ■ ■ ■            │
│ ──────────────────── │
│ ⊕ Save current  ⚙ Edit │
│ Custom…              │
└──────────────────────┘
```

- `PRESET` — сетка 8×2. `SAVED` — та же сетка с переносом, `max-height` со скроллом;
  имя (или hex, если имени нет) — в `title` и в `aria-label`. Пустая палитра
  показывает `No saved colors yet`.
- Свотч текущего цвета помечен `aria-pressed="true"` и кольцом. Сравнение —
  через `normalizeHex`.
- `Save current` раскрывает строку: поле имени (`placeholder="Name (optional)"`) и ✓.
  Enter сохраняет, Esc закрывает строку, не закрывая попап.
- `Edit` переключает `SAVED` из сетки в список строк «свотч · поле имени · ×».
  Переименование пишется по `change` поля, удаление — по клику ×.
- `Custom…` открывает нативный пикер программным `click()` по скрытому инпуту и
  **оставляет попап открытым**: подобранный цвет должно быть можно сразу сохранить в
  палитру, не открывая попап второй раз.

Позиционирование — `position: absolute` внутри обёртки свотча, с переворотом вверх и
влево по `getBoundingClientRect()`, чтобы попап не выехал за 340px панели. Открытым
может быть не более одного попапа: модуль держит ссылку на текущий и закрывает
предыдущий при открытии следующего.

### Взаимодействие с ре-рендером

Панель пересобирает `#app` целиком на каждое settled-изменение, а карточка настроек —
свои секции. Наивная реализация схлопывала бы попап при первом же клике по цвету,
поэтому попап встраивается в уже существующее разделение `commit`/`commitAndRender`
и ведёт себя как открытый нативный пикер — «пока открыт, идёт редактирование»:

| событие | колбэк | ре-рендер |
|---|---|---|
| клик по цвету в палитре | `onPreview` | нет |
| drag нативного пикера (`input`) | `onPreview` | нет |
| нативный пикер закрылся (`change`) | `onPreview` | нет |
| попап закрылся (Esc, клик вне, уход фокуса) | `onPick` | да |
| сохранение / переименование / удаление | `onPaletteChange` | нет |

`onPick` при закрытии шлётся только если цвет действительно менялся, пока попап был
открыт. Сторонние ре-рендеры попапу не страшны: `renderIfIdle()` в панели уже ничего
не делает, пока фокус внутри `#app`.

Корень `colorField` останавливает всплытие `input` и `change`. Иначе поле имени
внутри попапа помечало бы карточку настроек грязной через её листенеры на всплывающих
событиях — а палитра к профилю не относится. Все изменения и так идут через явные
колбэки; на всплытие никто не рассчитывает.

### Закрытие

Esc, `pointerdown` вне попапа, уход фокуса за пределы поддерева. Фокус возвращается на
кнопку-свотч. Пока открыт нативный пикер, закрытие по уходу фокуса подавлено:
браузерный диалог уводит фокус из документа, и без этого попап закрывался бы ровно в
тот момент, ради которого его оставили открытым. Флаг снимается по `change` инпута и
по возврату фокуса окну.

## Подключение

`rulesSection` и `faviconSection` получают два новых поля в options-объекте:
`palette: SavedColor[]` и `onPaletteChange(next: SavedColor[])`. Дальше:

- **Панель** — `onPaletteChange` → `commit({ ...settings, palette }, tab)`: тот же
  debounce-save, что у всех остальных правок.
- **Страница настроек** — палитра глобальная и не проходит через черновик карточки:
  пишется в storage сразу (`settingsRepo.save({ ...settings, palette })`), не трогая
  `dirtyProfileIds` и не помечая карточку грязной. Кнопка Save карточки палитры не
  касается: `touched` содержит только поля профиля.

## CSS

Всё новое — в `public/sections.css`, рядом с остальным общим: `.color-field`,
`.color-field .swatch-button`, `.palette-popover` и её внутренности. Существующие
правила `.section input[type="color"]` и `.field > input[type="color"]` переезжают на
кнопку-свотч, чтобы размер и рамка поля не изменились. Токенов и цветов, помимо
существующих в `tokens.css`, не добавляется.

## Доступность

Кнопка-свотч — `aria-haspopup="dialog"` + `aria-expanded`. Попап — `role="dialog"`,
`aria-label="Color palette"`. Свотчи внутри — кнопки с `aria-label` (имя или hex) и
`aria-pressed` у текущего. Ловушки фокуса нет: Tab идёт естественным порядком, а
уход фокуса за пределы попапа его закрывает.

- `src/shared/colorField.test.ts` (jsdom) — открытие и закрытие попапа; клик по

  только при изменившемся цвете; сохранение с именем и без; переименование и
  удаление зовут `onPaletteChange`; Esc закрывает и возвращает фокус; `input`/`change`

- `src/sections/rulesSection.test.ts`, `src/sections/faviconSection.test.ts` —
  секции прокидывают палитру и её колбэки.

## Что не делается

- Авто-«недавние» цвета.
- Палитры на профиль, импорт/экспорт, перетаскивание порядка.
- Форматы, кроме hex: правила пишут цвет в CSS, и `#rrggbb` — то, что уже проверяется
  на пути к нему.
- Отдельная секция Palette на странице настроек.
